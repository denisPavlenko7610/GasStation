## 1. Что было на старте

| Область | Состояние |
|---|---|
| Сцены | `Day` (с SubScene `Entities`) и `Night`, окружение из ассета «Gas station» |

## 2. Технический долг — исправить до начала геймплея

1. **`IAspect` устарел** в Entities 1.3 (будет удалён). Заменить `MoveToPositionAspect` на
   `IJobEntity` или `SystemAPI.Query<RefRW<LocalTransform>, RefRO<...>>`.
2. **`TargetPositionComponent` на деле хранит направление, а не позицию.** Разделить на
   `MoveInput` (направление от игрока) и `MoveTarget` (точка для NPC/машин). Использовать
   `float3`, а не `Vector3`: в компонентах ECS и Burst нужны типы из `Unity.Mathematics`.
3. **`MovingISystem`**: `[BurstCompile]` должен стоять и на struct, и на `OnUpdate`. Лучше
   перенести логику в `IJobEntity` и вызывать через `ScheduleParallel()`.
4. **`CameraSystem`**: `GetComponent` в `SystemBase` устарел, нужен `SystemAPI.GetComponent`.
   Случайный выбор игрока лишний — брать `SystemAPI.GetSingletonEntity<PlayerTag>()`.
   Смещение `-5f` зашито в код, а `CameraSingleton.CameraOffset` используется только по Y.
5. **Решить, какой будет игрок.** Сейчас одновременно есть ECS-игрок и MonoBehaviour-контроллер
   от первого лица. Рекомендация: игрок и UI остаются гибридом на MonoBehaviour/GameObject
   (контроллер, камера, взаимодействия, UI), а через ECS идёт массовая симуляция: машины,
   клиенты, очереди, топливо, экономика. Это самый простой путь и хорошо ложится на DOTS.
6. **Zenject + DOTS.** Zenject не внедряет зависимости в системы ECS. Оставить его только на
   Mono-слое (UI, сервисы, сохранения), а связь с ECS делать через singleton-компоненты или
   managed-синглтоны. Либо убрать Zenject совсем, чтобы не держать два способа связывания.
7. **Структура проекта:** папка `Envorinment` с опечаткой → `Environment`. Добавить
   `.asmdef` (`GasStation.Runtime`, `GasStation.Editor`, `GasStation.Tests`), чтобы ускорить
   компиляцию и изолировать тесты.
8. Настроить `.gitignore` для Unity (`Library/`, `Temp/`, `UserSettings/`, `.idea/`) и Git LFS
   для моделей и текстур.

## 3. Основной игровой цикл (MVP)

> Машина приезжает → встаёт в очередь → подъезжает к колонке → игрок заправляет →
> клиент платит → машина уезжает → игрок получает деньги → тратит их на улучшения.

### 3.1 Машины и трафик (ECS)
- `CarSpawnerSystem`: спавн префабов машин по таймеру и кривой интенсивности (зависит от
  времени суток и репутации). Компоненты `CarSpawner`, `CarPrefabBuffer` (`DynamicBuffer`).
- Движение по точкам: `Waypoint` в `DynamicBuffer<PathPoint>`, `CarMoveSystem` с
  плавным поворотом и торможением. На старте хватит заранее размеченных путей
  (въезд → очередь → колонка → выезд). NavMesh не нужен.
- Состояния машины: `enum CarState { Arriving, Queued, AtPump, Fueling, Paying, Leaving }`,
  плюс enableable-компоненты для быстрых фильтров в запросах.
- `CarDespawnSystem`: удаление через `EntityCommandBuffer` после выезда.

### 3.2 Колонки и очередь
- Сущность колонки: `Pump { FuelType, FlowRate, Occupant (Entity) }`, `PumpSlot`
  (точка остановки).
- `QueueSystem`: назначает свободную колонку, ведёт очередь (`DynamicBuffer<QueueEntry>`).
- Нетерпение клиента: `Patience { Current, Max }`. Если терпение закончилось, машина
  уезжает без оплаты, репутация падает.

### 3.3 Взаимодействие игрока
- Raycast / trigger через Unity Physics или с Mono-стороны: «взять пистолет»,
  «вставить в бак», «принять оплату».
- `FuelingSystem`: перекачка литров из резервуара в бак машины (`FuelTank { Current, Capacity }`),
  прогресс-бар над машиной.
- Позже: авто-режим, когда нанятый работник заправляет сам.

### 3.4 Топливо и склад
- `FuelStorage` (singleton): запас по типам (АИ-92, АИ-95, дизель), закупочная цена.
- Заказ бензовоза: событие → через N минут приезжает машина-заправщик и пополняет резервуар.
- Если топливо кончилось, колонка не работает.

### 3.5 Экономика
- Singleton `Economy { Money, Reputation, DayIncome, DayExpenses }`.
- Цена за литр задаётся игроком. От соотношения цены к «рыночной» зависит поток клиентов.
- Расходы: закупка топлива, зарплаты, электричество, аренда. Отчёт в конце дня.

### 3.6 Время суток
- `GameTime` (singleton): ускоренное время, день и ночь. Сейчас это две отдельные сцены
  `Day`/`Night`, лучше одна сцена с динамическим светом (Directional Light + Volume blend).
- Интенсивность трафика задаётся кривой по времени суток.

### 3.7 UI (uGUI или UI Toolkit, Mono-слой)
- HUD: деньги, время, репутация, запасы топлива.
- Попапы над машинами: сколько литров, какое топливо, терпение.
- Экраны: пауза, итоги дня, магазин улучшений, заказ топлива.
- Мост ECS → UI: одна `SystemBase` (`UIBridgeSystem`) раз в кадр читает singleton'ы и
  отдаёт данные в презентеры (сюда можно подключить Zenject).

## 4. После MVP

1. **Магазин при заправке**: товары (коробки уже есть в `Things`), полки, касса, выкладка
   товара, поставки.
2. **Улучшения**: новые колонки, быстрее насосы, больше резервуары, навес, мойка, шиномонтаж,
   зарядки для электромобилей.
3. **Персонал**: кассир, заправщик, уборщик. ECS-агенты с простым FSM или utility AI.
4. **События**: пиковые часы, грабитель, проверка, поломка колонки, скачок цен на нефть.
5. **Типы клиентов**: торопыга, эконом, грузовик (дизель, большой бак), такси с повторными
   визитами. Для разнообразия у машин есть `RandomComponent`.
6. **Прогрессия**: уровни репутации открывают новые машины и улучшения, ачивки.
7. **Сохранения**: сериализация singleton'ов и улучшений в JSON (`Application.persistentDataPath`).
   Машины на дороге не сохранять, сохранять только в конце дня.
8. **Звук и эффекты**: двигатели, шум заправки, касса, частицы, выхлоп.
9. **Оптимизация**: пулинг машин, LOD, Entities Graphics + GPU instancing, профилирование через
   Entities Profiler modules. Цель: 200+ машин и NPC при 60 FPS.

## 5. Тесты и инфраструктура
- EditMode-тесты систем через `World` + `EntityManager` (экономика, очередь, топливо —
  чистая логика, тестируется легко).
- CI: GitHub Actions + GameCI (`game-ci/unity-test-runner`, `unity-builder`) для тестов и сборки.
- Баланс в ScriptableObject-конфигах (цены, скорости, интенсивность) → в ECS через Baker'ы
  в blob assets.
